# 多语言本地化

> 基线：NewLife.Core 12 编译期词表｜运行时 31 种语言｜英文为源文与兜底

## 1. 语言分层

本库运行时词表与 NewLife.Core 的 31 种语言完全对齐（README 读者语言独立维持 11 种）。缺失译文在运行时自动回退英文，新增语言不需要改代码。

当前已登记 130 条词条（62 条运行时消息 + 64 条文档输出标签 + 4 条程序集元数据）。原有 126 条消息与标签在 31 种语言中均有译文，不存在英文回退占位；新增的 4 条程序集元数据处于迁移期（英文源文 + 简体中文），其余 30 种语言登记在 `tools/pending-translations.json`，由批量翻译阶段补齐。CI 使用 `-RequireTranslated -AllowPending` 校验，任何英文回退值都会失败。

## 2. 词表文件

- `NewLife.Office/Locales`

- 文件名即 BCP 47 语言代码；英文是源文与兜底，**不需要** `en.yml`。
- 键为**英文原文**，必须与代码字符串逐字一致（含空格与标点）；占位符 `{0}` 与格式说明符 `{1:n0}` 必须与英文一致。
- 词表由 NewLife.Core 包内的源生成器在编译期读取并生成压缩语言表，NativeAOT 下同样可用。

## 3. 新增一条消息

> 程序集元数据（`AssemblyTitle`/`Description`）与配置 `DisplayName`/`Description` 同样以英文源文入词表：csproj 写英文，`zh-Hans.yml` 写中文，其余语言在批量翻译阶段补齐。

1. 代码中写英文源文：`throw new XException("Session {0} is closed.", sessionId);`，日志直接写英文模板（`Logger.Format` 自动翻译）；禁止字符串插值，BCL 异常使用 `L.T(...)`。
2. 文档输出标签同样使用 `L.T(...)`，不要在输出中硬编码中文或英文；需要拼接时先取译文再拼接，避免把整段插值结果交给查表。
3. **阶段一（当前）**：先加英文源文与 `zh-Hans.yml` 译文，并把该键登记到 `tools/pending-translations.json`；其余语言缺失键在校验时降为告警。
4. **阶段三（批量翻译）**：补齐全部 31 种译文后，从待翻译清单移除该键；发布前清单必须为空。
5. 运行校验脚本确认键集合、占位符、格式说明符、代码→词表反向覆盖与翻译完整性。

## 4. 校验

```powershell
pwsh -File tools/check-locales.ps1 -LocaleDir NewLife.Office/Locales -SourceDir "NewLife.Office,NewLife.Office.Rendering,NewLife.Office.Cli" -RequireTranslated -AllowPending -PendingFile tools/pending-translations.json -ScriptCheck
pwsh -File tools/check-english-exceptions.ps1
pwsh -File tools/sync-readme-languages.ps1 -Check
pwsh -File tools/check-readme-languages.ps1
pwsh -File tools/sync-readme-package.ps1 -Check

# 一键运行以上全部检查
pwsh -File tools/verify-localization.ps1
```

- 词表校验同时做双向覆盖：词表中的每一条键必须在源码中找到（孤儿键，`.cs` 与 `.csproj` 均纳入），源码中每个 `L.T`/`Localization.Translate` 字面量必须已登记（防止静默回退英文）。
- 英文守卫会合并多行语句，检查异常、异常工厂（如 `ConvertErrorException.Unsupported`）、日志与控制台消息，并禁止字符串插值与未查表的异常消息。
- 词表校验的 `-ScriptCheck` 会对非拉丁语言做启发式书写系统检查，拦截整段英文复制；命中只告警，`-StrictScript` 可升级为失败。
- README 校验会比较 11 种译文与英文的标题/代码块结构、目标语言书写系统和整段英文残留；语义准确性仍需人工抽检。
- CI 的 localization job 会执行上述校验，其中词表校验启用 `-RequireTranslated -AllowPending`。
- **发布门禁**：改用 `-RequireTranslated -FailOnPending`，`tools/pending-translations.json` 必须为空。

### 4.1 迁移期待翻译清单

- `tools/pending-translations.json` 的 `keys` 列出「英文与简体中文已完成、其余语言待补」的键。
- 校验时缺失这些键只告警；未显式传 `-AllowPending` 时仍会失败，避免静默长期回退英文。
- 批量翻译阶段逐项补齐后移除；发布前 `-FailOnPending` 会强制清零。
- 阶段三前冻结英文源文：键就是英文原文，改词会导致全部译文失配。

## 5. 文档输出语言

除异常、日志、控制台与 CLI 等运行时消息外，词表还覆盖**文档输出标签**：

- 文本提取输出的标签（如“幻灯片 N”“第 N 页”“脚注/尾注”、iCalendar/vCard/邮件字段、修订作者）；
- 模板与文档默认值（Word 内容控件占位文本、PPT 默认节名、Excel 切片器名称、数据透视空白项、图表类别表头）；
- EPUB 写入时的“目录/封面”HTML 文本。

这些文本与运行时消息共用同一词表，按 `Localization.Culture`（默认 `CurrentUICulture`）在**生成时**翻译。若调用方需要固定输出语言，可在生成前设置 `Localization.Culture`。

以下内容不参与翻译：

- 字体名（宋体、微软雅黑、等线等）与字体族标识；
- OOXML/CFB/ZIP 内部元素名、部件名与固定协议标识；
- 用于格式识别的样式名前缀（如 `Heading`、`标题`）；
- 文档自身的业务数据（标题、正文、联系人姓名等）。

## 6. NuGet 包信息

- `Description` 保持纯英文，供反射与 NuGet 页面使用；`PackageDescription` 可中英双语；`PackageTags` 保留中英关键词。
- `README.nuget.md` 由 `tools/sync-readme-package.ps1` 从英文 `README.md` 生成，相对链接改写为 GitHub 绝对地址；主包与渲染扩展均通过 `PackageReadmeFile` 打包。
- nuget.org 的包元数据不随界面语言切换；运行时关于页、服务注册等展示点调用 `Localization.Translate(AssemblyTitle/Description)` 获得本地化文本。
- CI 执行 `sync-readme-package.ps1 -Check`，防止生成物与英文 README 漂移。

# NewLife.Office 架构设计

> 版本：v1.2 | 日期：2026-11-03
> 需求对应：[需求文档](需求文档.md) | 功能清单：[功能清单](功能清单.md)

## 1. 整体架构

NewLife.Office 采用**分层 + 模块化**架构，按文件格式组织为独立模块，共用 OLE2/CFB 二进制基础层，并通过统一转换层与渲染扩展包提供跨格式能力。


### 1.1 分层职责

| 层 | 职责 | 说明 |
|----|------|------|
| **格式模块层** | 各格式读写/模板/转换 | 每个格式独立目录，Reader/Writer/Model 三件套 |
| **OLE2/CFB 基础层** | 老式二进制容器 | xls/doc/ppt/msg 共用，避免重复解析 |
| **统一转换层** | 文档 → Markdown | `IMarkdownDocumentExtractable` 统一 AST，单一序列化器 |
| **渲染扩展包** | 文档 → 图片 | 独立 NuGet（依赖 SkiaSharp），与主库零依赖定位隔离 |
| **统一入口** | 便捷 API | `OfficeFactory.ReadText/ReadMarkdown/CreateReader` |

### 1.2 核心设计原则

1. **零外部依赖**：主库仅依赖 `NewLife.Core`，直接操作 ZIP + XML / PDF / OLE2 底层结构，避免中间层开销
2. **保真架构**：按格式复杂度采用 L2/L3 级保真（见 §3），确保读→改→写往返不丢内容
3. **统一模型**：每个格式有完整对象模型（Models/），Reader 填充模型、Writer 从模型重建
4. **模型 + RawXml 透传兜底**：模型覆盖常用属性，未建模属性通过原始 XML 透传保留
5. **跨格式转换**：Markdown 为统一 AST 中枢，各格式实现转换接口即可输出 GFM Markdown

### 2.1 M — Excel（xlsx/xls）

#### 职责

| 职责 | 说明 |
|------|------|
| xlsx 读写 | 直接操作 ZIP + sheet/worksheet + sharedStrings + styles |

| 模板填充 | 占位符替换 + 列表区域扩展 |

| 组件 | 所在工程 | 说明 |
|------|----------|------|
| `ExcelWriter` | NewLife.Office | xlsx 写入器（partial：主文件/Internal/Save），样式管理 + XF 缓存 |
| `ExcelReader` | NewLife.Office | xlsx 读取器，自动类型转换，`ReadObjects<T>` |
| `ExcelTemplate` | NewLife.Office | xlsx 模板填充 |
| `BiffReader`/`BiffWriter` | NewLife.Office | xls BIFF8 读写（复用 OLE2/CFB 层） |
| `CellStyle`/`Models/*` | NewLife.Office | 样式模型（CellFormat/ConditionalFormatting/DataValidation 等 18 模型） |
| `PivotBuilder` | NewLife.Office | 数据透视表构建 |

#### 关键流程：xlsx 读写往返

```mermaid
sequenceDiagram
  participant U as 调用方
  participant W as ExcelWriter
  participant R as ExcelReader
  U->>W: WriteHeader/WriteRow/CellStyle
  W->>W: 样式去重 + XF 缓存
```

#### 设计要点
- **样式管理器**：内部组件去重 + XF 缓存，避免 styles.xml 膨胀
- **长数字保护**：Int64 使用整数样式，避免科学计数法；身份证号/前导零文本化
- **BIFF8**：SST 共享字符串 + XF/FONT/FORMAT 样式记录 + MERGEDCELLS/HYPERLINK 等扩展记录

```mermaid
sequenceDiagram
  participant A as Agent
  participant T as CLI / MCP
  participant R as Reader
  participant P as Patch
  participant W as Writer
  A->>T: read_outline(path)
  T->>R: 读取（按扩展名/内容识别路由）
  R-->>A: 结构快照 + 锚点（p#3 / Sheet1!A1 / s#2/shape#5 / 页码+矩形）
  A->>T: apply_patch(path, output, ops)
  T->>P: 逐条执行并记录失败
  alt 全部成功
    P->>W: 保存到 output
    W-->>A: ok
  else 任一条失败
    P-->>A: 结构化错误（不写文件）
  end
```

#### 设计要点
- **锚点是快照内序号/坐标**：不做跨版本持久化，改动后必须重新读取，避免用过期位置改新文档
- **补丁原子性**：内存模型可部分修改，但只有全部成功才写出文件；失败时调用方必须重读源文件
- **手写 JSON 序列化**：不引入序列化依赖（手写 `ToJson` / 轻量 `JsonLite`），保持零依赖与 AOT 友好
- **与保真架构协同**：docx 走 `BeginEdit()` 关闭透传再改；xlsx/pptx/pdf 复用具名部件透传能力，未建模内容原样保留
- **PDF 对象级重写**：`PdfObjectDocument` 保留原对象表与内容流，只改页面树/标注/元数据后整份重写；加密 PDF 拒绝修改，叠加文字限 Helvetica（Latin-1）
- **不可信输入的资源边界**：`JsonLite` 嵌套深度上限 256（防栈溢出），`ExcelSearch`/`PdfTextSearch` 的正则匹配超时 1 秒（防灾难性回溯），超限统一返回 `ResourceLimit` 错误码

## 3. 保真架构（L2/L3 级）

NewLife.Office 按格式复杂度采用不同保真等级，核心目标是**读→改→写往返不丢内容**。

| 等级 | 格式 | 策略 | 往返保证 |
|------|------|------|---------|
| **L3** | Word docx、PDF | 完整对象模型 + RawXml 透传兜底 + ZIP 部件完整透传（docx）/ 对象级解析 + 内容流重建（PDF） | 不改动 = 字节级等价；改动 = 视觉级等价 |
| **L2** | PPT pptx | 完整对象模型 + 媒体/母版 ZIP 部件透传 | 媒体字节一致 + 视觉等价 |
| **L1** | 轻量格式（RTF/ODS/EML/ICS/VCF/EPUB/XPS） | 完整对象模型 | 结构级等价 |
| **L0** | 二进制只读（doc/ppt/xls） | 解析提取；ppt 已补最小写入（PptWriter 文本幻灯片） | 只读为主，ppt 基础写入 |

### 3.1 L3 关键决策（Word）

- **Element.RawXml 保留**：每个元素保存原始 OuterXml，Writer 在模型字段为 null 时回退写 RawXml → 未建模属性（删除线/高亮/字符间距/段落边框）不丢失
- **ZIP 部件透传**：`CollectOtherParts()` 收集非 document.xml 部件，透传模式仅重建 document.xml
- **权衡**：模型体积大 vs 保真度高——选择保真（对比：纯模型方案丢失格式，纯 XML 方案丢失可编程性）

### 3.2 L3 关键决策（PDF）

- **对象级解析**：xref → 对象解析器 → 内容流操作符序列，支持修改后重建
- **权衡**：重建复杂度高 vs 字节级复制无法修改——选择对象级（满足水印/覆盖/表单填充等编辑需求）

## 4. 设计决策

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 底层实现 | Open XML SDK / 直接操作 ZIP+XML | 直接操作 | 零外部依赖、避免中间层开销、性能优先 |
| 依赖策略 | 依赖第三方库 / 仅 NewLife.Core | 仅 NewLife.Core | 与 NewLife 生态一致，包体积 <500KB |
| Markdown 定位 | 孤立解析器 / 全格式转换中枢 | 全格式中枢 | 全格式双向转换差异化，喂 AI 知识库 |
| 渲染能力 | 内置主库 / 独立扩展包 | 独立包（Rendering） | 零依赖定位与 SkiaSharp 冲突，拆包隔离 |
| 保真等级 | 纯模型 / 模型+RawXml / 纯 XML | 模型+RawXml（L3） | 可编程性 + 保真度兼得 |
| 老格式支持 | 不支持 / 只读 / 读写 | 只读（doc），xls 读写，ppt 读写（文本级） | 需求聚焦迁移场景；ppt 写入仅文本幻灯片最小可用 |
| xls 写入 | 重写全部 BIFF8 / 基于 CFB 层 | 基于 CFB 层 | OLE2/CFB 为 xls/doc/ppt/msg 共用基础 |
| 图片渲染路由 | 各格式独立渲染 / PDF 中转 | PDF 中转 | 一处 PDF 渲染管线，Word/PPT/MD 复用 |
| API 风格 | 各格式独立 API / 统一入口 | 独立 API + OfficeFactory | 格式差异大，独立 API 更清晰；统一入口提供便捷 |
| 内容识别 | 扩展名判断 / magic bytes | 扩展名判断（规划 magic） | 当前以扩展名为准，内容识别（magic bytes）为远期演进方向 |
| 编辑入口 | 手工清两层缓存 / `BeginEdit()` 显式进入编辑态 | `BeginEdit()` | 手工清缓存是高频静默失败源；显式入口可标记编辑态、收集未建模内容诊断 |
| 修改丢失防护 | 静默忽略 / 保存前自检报错 | 保存前自检 | `BodyModified` 且仍开 `DocumentXml` 透传时抛异常；不动内部件（页眉页脚/脚注）不误报 |
| 未建模内容策略 | 全面就地改 XML / 登记并原样保留 | 登记 + 原样保留（折中） | 全面就地改 ≈ 重写编辑引擎；`ElementType.Unknown` + `RawXml` 保留可覆盖约 95% 真实文档 |
| 语义编辑 API | 下标操作 / 按语义定位+增删改 | 语义定位+增删改 | 下标操作文档一变就错位，AI 生成代码极易写错 |
| 各节页眉页脚 | 全局扁平引用 / 每节独立内容 | 每节独立（`Section.Headers/Footers`） | OOXML 的“链接到上一节”本质就是“本节不写引用、继承上一节”；显式链接标志 + 本节内容模型可双向表达链接与断链，链接节不输出引用避免读写语义漂移 |
| Markdown 图片与页眉页脚 | 总是输出占位 / 读取时置入图片字节并由选项控制 | 选项控制（`MarkdownConverterOptions`） | 默认保持历史输出；需要图片文件时用 `ImageDirectory` 落地并由 Markdown 按文件名引用（Agent 可直接打开图片），页眉页脚仅在显式开启时以引用块输出，避免污染正文 |
| 生成的属性元素顺序 | 按模型字段顺序随手拼接 / 严格按 OOXML schema 顺序 | 严格按 schema 顺序 | `rPr`/`pPr`/`tcPr`/`sectPr` 子元素顺序错会让 OpenXmlValidator 判为 "unexpected child element"、第三方工具报文件损坏；实测真实样张错误数从 532 降到 30（源文件 31），`SchemaOrderTests` 守卫顺序 |
| 页眉页脚部件的关系文件 | 只写 XML / 连同源部件 rels 一起写回 | 一起写回（`Header.RelsXml`/`Footer.RelsXml`） | 页眉 logo 走 `<a:blip r:embed>` 引用部件自身 rels；只写 XML 会留下悬空引用（严格校验报错），读入内容因此能无损往返 |
| 提取失败的可见性 | 静默返回 null / 记录失败原因 | `LastError` 属性 | 提取入口以「null = 无法转换」为契约，但 null 分不清"空文档"和"解析出错"；改为把原因记在属性上，返回契约不变（不破坏调用方） |
| PPTX 演讲者备注 | 内联在 slide XML 的 `p:notes` / 独立 notesSlide 部件 | 独立部件 | `p:notes` 不是 `p:sld` 的合法子元素，内联写法被严格校验判错、PowerPoint 打开即丢备注；备注必须落在 `ppt/notesSlides/notesSlideN.xml` 并配 notesMaster 与关系 |
| PPTX 转场时长与 morph | `p:transition dur="…"` + `p:morph` / `mc:AlternateContent` + `p14:dur` + `p15:morph` | 后者 | ECMA-376 的 `p:transition` 只有 `spd`/`advClick`，`dur` 属 p14 扩展、morph 属 p15；扩展元素必须包在 `mc:AlternateContent` 内（带 Fallback），否则严格校验报 "attribute not declared" |
| PPTX 元素落点 | 就近写在 presentation/slide 根下 / 按各 part 的 CT 定义落点 | 按 CT 定义 | 背景属 `p:cSld` 子元素、页眉页脚数据在 `CT_Presentation` 无对应子元素（改放 `extLst` 自建扩展）、presentation 必须按 sldMasterIdLst→sldIdLst→sldSz→notesSz→…→extLst 排列 |
| XLSX 图表关系挂载点 | worksheet 直接关联 ChartPart / 只挂在 drawing 部件 | 只挂 drawing | SpreadsheetML 不允许 worksheet 直接 target ChartPart；图表必须经 drawing→chart 两级引用，且 drawing 部件必须有独立 Content-Type Override（否则落回 `application/xml`，Excel 判定文件损坏） |
| 图表系列结构 | 所有图表统一 `c:val` / 按图表类型分别输出 | 按类型分别输出 | 散点/气泡系列的 schema 是 `xVal`+`yVal`（+`bubbleSize`），统一写 `c:val` 会被判非法；股价图要求 3~4 条系列、曲面图要 3 个轴 ID，写出前自动补足 |
| 切片器与线程批注部件 | 自拟根元素 / 按 MS-XLSX 定义 | 按定义 | `xl/slicers/slicerN.xml` 根必须是 `x14:slicers` 容器、`slicer` 只有属性；`xl/persons/person.xml` 根是 `personList`、日期属性是 `dT`。根元素写错会让整包无法打开（不是"仅该功能失效"） |
| 单元格样式生效时机 | 写入时即固化行 XML / 保存前统一回填覆盖 | 保存前回填 | 行 XML 在 `WriteRows` 时就生成，"先写数据、后调 `SetCellFormat`"的样式会被静默丢弃（实测 API 完全无效）；改为 Save 前统一应用覆盖，并沿用原数字格式避免日期被覆盖成常规 |
| AI 接口形态 | 直接暴露 Reader/Writer 对象 / 结构快照 + 锚点补丁 | 结构快照 + 补丁 | 模型凭记忆猜结构会改错位置；补丁整批校验可把"改一半"挡在落盘前，且四格式可共用同一套调用范式 |
| 模型与 RawXml 的优先级 | 全局清 RawXml / 只清被编辑元素 | 只清被编辑元素 | 元素级 RawXml 在 Writer 里优先于模型，编辑前不清会让改动静默丢弃；全局清又会让未触碰内容退化为模型重建，故按元素清理，并把"未建模内容会丢失"写进 `EditWarnings`，经 `DocxPatchResult.Warnings` 回传 |
| 分页符段落 | 只输出 `w:br` / 输出 `w:br` 后继续输出 Runs | 后者 | 真实文档存在"分页符 + 文本"同段；旧实现整段只当分页符输出，`set_text` 改了模型却不落盘（实测静默失败）。改为 br 之后照常输出 run，并剔除模型里表示分页的 `\f` 字符 |
| 节属性落点 | 每节末尾追加空段落承载 `sectPr` / 附加到本节最后一段 | 附加到最后一段 | 追加空段会让每次保存多出一个空段落（多节文档反复编辑持续膨胀）；节尾不可建模时才回退到空段落 |
| 文本部件 BOM | 直接写解码后的文本 / 写入前剥离 BOM | 剥离 BOM | 从 byte[] 解码的文本已含 BOM 字符，`StreamWriter` 再加一个，形成双 BOM（`EF BB BF EF BB BF`），Word 与严格解析器判文档损坏 |
| 运行时消息语言 | 异常/日志/控制台直接写中文 / 英文源文经 `L.T()` 查表 | 英文源文 + 查表 | CI 门禁 `check-english-exceptions.ps1` 禁止中文与字符串插值消息；键为英文源文，`Locales/zh-Hans.yml` 为基准译文，其余 30 语言缺失时登记 `tools/pending-translations.json` 并回落英文 |
| 补丁失败分类 | 按失败消息文本匹配关键词 / 按异常类型编码 | 按异常类型 | 消息已本地化，文本匹配在非中文区域文化下会失效（`AnchorMissing` 退化为 `Malformed`）；改为补丁结果携带 `FailedCodes`（异常类型名），`ArgumentException`/`ArgumentOutOfRangeException` → `AnchorMissing`、`NotSupportedException` → `Unsupported`，与消息语言解耦 |

## 5. 关键设计决策（被否决的替代方案）

| 决策 | 被否决方案 | 否决理由 |
|------|-----------|---------|
| 底层实现 | 基于 Open XML SDK | 引入外部依赖，与零依赖定位冲突；间接层影响性能 |
| 渲染能力 | 内置主库 | 破坏主库零依赖承诺，包体积激增；拆分后主库/Rendering 各取所需 |
| PDF 编辑 | 字节级复制（合并/拆分仅重排对象） | 无法满足内容流级修改（水印/覆盖/表单填充）；对象级重建成本可控 |
| Word 保真 | 纯对象模型 | 未建模属性（高亮/边框/域代码等）丢失；RawXml 兜底成本低收益高 |
| Markdown 输出 | 各格式各自拼字符串 | 格式不一致、难维护；统一 AST + 单一序列化器保证一致性 |
| Word 编辑保真 | 严格就地修改 document.xml 全部节点 | 工作量约等于重写一套编辑引擎；未建模内容登记保留已能覆盖真实文档绝大多数场景，且实现只需新增 Unknown 元素与 Run 级保真，成本可控 |
| Markdown 图片落地 | 内嵌 data URI（base64）为默认 | 体积随图片线性膨胀、base64 对 Agent 无额外价值；改为“选项开启时落地文件 + 文件名引用”，需要内嵌时显式选 `Embed` |
| AI 操作文档 | 让模型自行遍历对象树逐条修改 | 无稳定锚点、也无回滚，改一半就留下损坏文件；把定位（快照）与原子性（补丁）收进库内，模型只负责选锚点和写新值 |
